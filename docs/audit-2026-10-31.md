**1. The Jan 1 year archive removes December shifts from every cheque, week, overtime, badge and widget figure** · BUG · High · INSP + EXEC (week totals) [re-checked]

- **Where:**
  - `HoursStore.swift:2307-2341`: `archivePriorYearsIfNeeded` runs on every foreground and is on by default.
  - Readers that look only at `store.entries`, so they lose the archived shifts:

    | Reader | Location |
    |---|---|
    | Overtime week buckets | `HoursStore.swift:1524-1541` |
    | Cheque detail | `PayCycleDetailView.swift:32` |
    | Home week/cheque tiles | `HomeSections.swift:283,294` |
    | History | `HistoryTabView.swift:173,238,294` |
    | PDF statement | `PayPeriodStatementPDF.swift:51` |
    | Shift earnings card | `ShiftEarningsCard.swift:58,89` |
    | Widget | `WidgetDataManager.swift:103-121` |
    | Own row on the friends board | `FriendsView.swift:57`, `HomeListsSections.swift:151` |
    | Published cheque hours | `CloudSyncManager.swift:1829` |
    | Badges and the badge summary published to friends | `AchievementBadges.swift:41` |
    | Cheque projection | `HoursStore.swift:1948-1972` |

- **Example:** a pay cycle runs Dec 22 2026 – Jan 4 2027, with Dec 28–31 and Jan 1–3 worked at 8h each and a weekly OT threshold of 40. On Jan 1:
  - the cheque shows 24h instead of 56h;
  - the week of Dec 28 has 0h of overtime instead of 16h;
  - all 2026 cheque rows disappear from History;
  - lifetime badges re-lock;
  - the widget streak shows 0.
- **Fix:** have pay-cycle, week, badge and widget readers use `allEntriesIncludingArchive()` (already memoised). Alternatively, only archive entries whose pay cycle and pay week closed before Jan 1.

**2. Signing out and into another account uploads the first account's shifts into the second** · BUG · High · INSP

- **Where:**
  - `CloudSyncManager.swift:1245-1310`: `handleSignedOut` keeps local entries.
  - `CloudSyncManager.swift:1217-1226` and `:1311-1357`: on sign-in, `migrateLocalDataIfNeeded` runs `syncAll` or merges.
  - `HoursStore.swift:281-286`: local-only entries are re-uploaded.
  - `CloudSyncManager.swift:369+`: the daily repair runs for the new uid.
- **Repro:** sign in as A with 100 shifts, sign out, sign in as B. B's cloud and leaderboard now contain A's shifts.
- **What else leaks into B:**
  - display name (`profile_display_name`);
  - company and occupation;
  - privacy flags;
  - pay settings;
  - templates;
  - pending queues;
  - supporter flag;
  - possibly prestige.
- **Fix:** store a `local_data_owner_uid`. If a different uid signs in, wipe local account state (reuse `deleteAllData` plus the queues) before listeners or repair start, or ask the user first.

**3. Deleted shifts come back from other devices and from the daily repair** · BUG · High · INSP

- **Where:**
  - `HoursStore.swift:283-286` and `:2185-2194`: a local entry missing from the snapshot is treated as created offline and re-uploaded.
  - `CloudSyncManager.swift:279-305`: the repair uploads all entries.
  - `index.js:1586`: the server accepts an id it has never seen.
  - Tombstones are per device, in UserDefaults.
- **Repro:** phone A deletes shift X. Phone B still holds X and re-creates it on its next snapshot or repair. Server totals rise again, and A permanently hides X while the server counts it.
- **This is the root cause behind the earlier note that server deletes get resurrected.**
- **Fix:** keep server tombstones in `users/{uid}/deletedEntries/{id}`. The upload callable rejects ids that have one, and clients listen for them.

**4. An offline edit is overwritten by the cloud copy** · BUG · High · INSP

- **Where:**
  - `HoursStore.swift:257-259`: remote replaces local with no `modifiedAt` comparison.
  - `CloudSyncManager.swift:1746-1755`: reconnect never replays `pending_entries`; it is only used as a counter.
- **Repro:** edit a shift offline, then relaunch. The cached or server snapshot reverts the edit, and the reverted copy is then uploaded.
- **Fix:** keep the local copy when `local.modifiedAt > remote.modifiedAt` or when its id is pending, and re-push it.

**5. Clearing a stat-holiday rule never reaches the cloud, and the edit reverts on the device** · BUG · High · EXEC (test) [re-checked]

- **Where:** `WorkEntry.swift:158-159` uses `encodeIfPresent(holidayPayRule)` and only writes `statPayHours` when it is above 0. Cloud writes use `merge: true`.
- **Repro:** save a "stat pay only" day, then edit it into a normal work shift. Firestore keeps `statPayOnly` and 8h, and the listener restores them within about a second, so pay still includes stat pay.
- **Fix:** `encode` both fields, writing null and 0, the same way latitude and longitude already are.

**6. Direct writes to `entries` bypass the last-writer-wins guard, so the two collections drift apart** · BUG · Medium-High · INSP

- **Where:**
  - `firestore.rules:191-193`: no stamp check on `entries`.
  - `CloudSyncManager.swift:146`: an unguarded direct write.
  - `:1751`: `syncAll` re-saves the whole history after any offline session.
  - `entryWriteGuard.js:22`: the comment claims "device adopts server copy", but clients listen to `entries`, not `timeEntries`.
- **Effect:** one device's stale copy reverts another device's edit on both phones, while server stats keep the newer version.
- **Fix:** make the callable the single writer of both collections, or add a stamp check to the `entries` rules. `syncAll` should send pending ids only.

**7. "Show hours to friends = off" still pushes per-shift hours to friends** · BUG · High (privacy) · INSP [re-checked]

- **Where:** `HoursStore.swift:1395-1411` builds the body "worked 9.5h today". `ActivityFeedService.swift:48` only checks `shareActivity`, and `index.js:272+` pushes the body as-is.
- **Fix:** omit the hours when `shareHours` is false, on the client and enforced on the server.

**8. Privacy toggles reset to "share everything" on a new device or reinstall** · BUG · Medium-High (privacy) · INSP [re-checked]

- **Where:** `SocialPrivacySettings.swift:94-104` defaults every flag to true from UserDefaults. Nothing adopts the cloud `users/{uid}.privacy`, and the first profile snapshot then publishes `shareHours: true`.
- **Fix:** adopt the cloud privacy settings on sign-in before the first snapshot, the same pattern as `adoptCloudAlertPreferences`.

**9. Private profile data is readable, and listable, by any signed-in user** · BUG (rules) · Medium-High (privacy) · INSP [re-checked]

- **Where:**
  - `firestore.rules:176`: `users/{uid}` allows read, which includes list.
  - The doc carries `timeZone`, app build, `tipTotal`/`tipCount`/`lastTipAt`, company, the privacy map, `friendCode`, and any leftover `fcmToken` or `lookupEmail` from old builds.
  - `publicProfiles` (`:73`) carries daily cheque hours, week/month/year hours and company even when the Settings copy says "Friends see…".
  - `presence` is listable.
- **Fix:**
  - Allow `get` only on `users`, with friend-code lookup through a callable.
  - Move tips and other private fields to a private subdoc.
  - Split `publicProfiles` into a public part and a friends-only part.

**10. On a small phone at large text, the onboarding pay page cannot be completed** · BUG · High for affected users · EXEC (iPhone SE sim screenshots)

- **Where:** `OnboardingView.swift:465` is a plain VStack with no ScrollView. The name page (`:299`) and photo page (`:387`) have the same problem.
- **What happens:** at AX-L the title is truncated, the footer runs under the page dots, and there is no Continue button.
- **Fix:** wrap these pages in the ScrollView plus min-height frame that `signInPage` already uses.

**11. Firestore cost grows with the square of the user count: every shift triggers 3–4 full leaderboard rebuilds** · BUG (cost) · High at scale · INSP [re-checked]

- **Where:**
  - `recompute.js:1517-1525`: the "delta" is a deliberate full rebuild that reads every `boardHours` and `publicProfiles` doc and rewrites the board.
  - It runs from `onTimeEntryWritten`, `recomputeUserStatsCallable` and the delete callable.
  - Each shift save also fires the mirror callable recompute, the trigger, the debounced recompute, and a listener-echo profile sync recompute.
  - `HoursTrackerApp.swift:101` runs the full refresh on inactive→active. Pulling down Control Center, Face ID, or a StoreKit sheet each re-reads the full `entries` collection and triggers more rebuilds.
- **Estimate:** about 1.4M reads/day at 150 users; about 75M/day at 1,500 users.
- **Fix:**
  - Make the per-write board update a dirty flag reconciled by the 15-minute job.
  - Skip unchanged `stats`/`publicProfiles`/board writes.
  - Act only on background→active.
  - Hash the profile snapshot and skip the write when it is unchanged.

**16. Push spam via friend requests, plus unmoderated public text** · BUG (rules) · Medium · INSP

- **Friend requests:** `firestore.rules:239-252` lets the sender create, delete and re-create `friendRequests` with any `fromName`. Every create pushes the recipient (`index.js:678`), with no rate limit.

- **Fix:**
  - Make friend-request creation server-only (the callable already exists).
  - Filter and cap those fields.
  - Restrict photo URLs to the project's bucket.

**17. Overnight shifts across a clock change are off by one hour, and the live timer disagrees with the saved shift** · BUG · Medium · EXEC (test)

- **Where:** `WorkEntry.swift:55` adds a fixed +24h. The same logic is copied in `EntryEditorView.swift:416-423` and `AddShiftWizardView.swift:592-599`.
- **Repro:** in Toronto, 10 PM Oct 31 → 6 AM Nov 1 saves as 8.0h; the real duration is 9h. The live timer shows 9h but the saved shift is 8h.
- **Related, split at midnight:** on a DST day the first portion is wrong (`OvernightSplit.swift:68-73`): 1h or 3h instead of 2h.
- **Fix:** build the real end date with `Calendar` and then subtract. Store the split's first portion with `end: nextDay`.
- **Who is affected:** this Mac's tz database shows no fall-back for Edmonton or Vancouver after Oct 2026. Alberta and BC users are likely unaffected; Ontario and US users are affected.

**18. Shifts move to the previous day when viewed in a zone west of where they were logged** · BUG · Medium · EXEC

- **Where:** `WorkEntry.date` is an absolute instant, and everything buckets it with `Calendar.current`.
- **Example:** an Edmonton Thursday shift viewed in Vancouver becomes Wednesday. It changes month, weekday and weekend premium, and the auto-filler adds an "Off" day for the day that now looks empty.
- **Fix:** persist a zone-independent day key (or the logging zone) on each entry.

## Checked and found sound

- **Single pay function:** every on-device pay number (Home, cheque, History, PDF, report export, earnings card, live shift, milestones, Wrapped) comes from `payBreakdown`.
- **Pay rules:**
  - breaks are taken before OT;
  - a break longer than the shift clamps to 0;
  - daily OT → double-time order is correct;
  - holidays are excluded from the weekly cap;
  - week-bucket caches are invalidated correctly.
- **Server vs client:** `paidHours` and the cheque window match.
- **Admin gate:** all `admin*` callables check the admin uid; client admin UI is gated by uid.
- **Sign-in:** the Apple nonce is handled correctly.
- **Listeners:** no duplicate listeners; all are removed on sign-out; `[weak self]` everywhere; the live-shift and friends timers are invalidated.
- **Backup restore:** dedupes against both active and archived entries.
- **Stale memory note:** the prestige backstop gate fix (memory said "uncommitted") is in HEAD as `7c35af3`.
